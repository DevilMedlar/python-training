# Research protocol template

Copy this into the learner's own work and fill it before the final experiment.
Record revisions and label post-result changes exploratory. No blank field is
evidence of a completed research step.

| Field | What to supply |
|---|---|
| Question and scope | Method, comparison, conditions, outcome, population/workload |
| Claim type | Descriptive, predictive, causal, theoretical, or engineering |
| Prior work | Primary references actually inspected and relevant differences |
| Baseline | Credible implementation, configuration, and budget |
| Experimental unit | What constitutes an independent replicate and why |
| Inputs | Provenance, schema, inclusion rules, preprocessing, splits |
| Primary outcome | Definition, units, desired direction, aggregation |
| Uncertainty | Method, assumptions, pairing/clustering, multiplicity policy |
| Randomness | Generator, seed, task identities, stream mapping |
| Execution | Commands, code commit/dirty state, resolved configuration |
| Environment | Interpreter/build, dependencies, native libraries, hardware |
| Timing scope | Setup, compilation, transfer, synchronization, measurement |
| Verification | Known answers, invariants, independent comparisons, tolerances |
| Failures/exclusions | Handling and reporting rules fixed before final results |
| Stopping rule | Replications, budget, and criteria for ending the study |
| Agreement criterion | Bytes, numeric tolerance, or scientific conclusion |
| Outputs | Raw records, logs, analysis scripts, figures, report |
| Limits | Alternative explanations and claims the study cannot establish |
| Revisions | Date, reason, and whether results were already inspected |

At the end, connect each claim to an output and each output to raw input and
configuration. Explain a result that did not fit the initial expectation.
