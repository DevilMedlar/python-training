The current browser-only instruction governs how the supplied material is taught.
The GitHub draft's local setup is source history, not a learner requirement;
GitHub actions are integrated into each Python lesson. The newly attached copies
were used to confirm the topic progression and teaching approach while preserving
the existing Python lesson content. The manifest below records the earlier intake.

All eight user-supplied drafts informed this rebuild and its GitHub addition. Originals are not republished
as authoritative teaching files. This avoids contradictory instructions and
unreviewed draft content being loaded as the active tutor protocol. The hashes
in [input-manifest.json](input-manifest.json) identify the exact supplied bytes.

The original seven-file collection contains approximately 58,000 words. Headings, tables,
code blocks, and Word hyperlinks were extracted for intake. Repeated reading
lists and speculative schedules were condensed into a source map and explicit
lesson decisions. Specialist breadth is preserved as optional paths rather than
an encyclopedic requirement for every learner. Technical code and claims carried
forward have the bounded checks documented in [CLAIM_AUDIT.md](CLAIM_AUDIT.md).
This is a curated reconstruction, not a sentence-by-sentence certification of
all 58,000 original words or all linked resources.

The additional GitHub Markdown file contains 7,973 whitespace-separated words,
29 numbered sections, and 67 distinct URLs. Its source-authored verification notes
were treated as claims to check, not as our execution record. The
[GitHub audit](GITHUB_AUDIT.md) maps all 29 sections to the companion lessons or
reference, records primary checks and reproduced examples, and identifies limits.
